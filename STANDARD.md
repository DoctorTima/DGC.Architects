# Стандарт интерактивных статей журнала DGC.Architects

Версия 1, 23.11.2026. Написан по итогам REC и «Долины». Каждая новая статья делается по этим правилам и проходит проверки из раздела 9 до выпуска.

## 1. Главный принцип: статья работает на любом устройстве

Каждая статья собирается слоями. Каждый следующий слой только добавляется к предыдущему, а не заменяет его:

1. **Текст, чертежи, рендеры.** Есть всегда, даже если скрипты не запустились. Если скрипт журнала не стартовал за 8 секунд, страница показывается целиком как обычный текст.
2. **Кадры модели.** Заранее снятые кадры той же 3D-сцены. Их видят:
   - читатели в облегчённом режиме;
   - все, пока грузится живая модель;
   - все, если 3D не запустилась.
3. **Живая 3D.** Только там, где устройство её потянет.

Сбой любого слоя не блокирует страницу: она прокручивается дальше, на месте 3D остаются кадры. Плашки поверх сцены и ожидание «модель загружается…» без конца запрещены.

## 2. Классы устройств

Определение делает скрипт в шапке страницы (`page.html`). Результат лежит в `window.DGC_ENV`, на `<html>` добавляются классы `lite` и `in-app`.

| Класс | Как определяется | Что получает |
|---|---|---|
| Облегчённый (`lite`) | нет WebGL 2; iOS ниже 16; Android с памятью до 2 ГБ; экономия трафика | кадры вместо 3D, кнопка «Включить 3D-модель» (если есть WebGL 2); тяжёлые файлы не скачиваются |
| Встроенный браузер (`in-app`) | Instagram, Telegram, Facebook, VK, OK, TikTok и др.; iOS без слова Safari; Android WebView (`; wv)`) | живая 3D с исправлением загрузки текстур, кадры как запасной вариант |
| Обычный | остальные | живая 3D, кадры пока грузится |

Кнопка «Включить 3D-модель» ставит `sessionStorage['dgc-3d'] = 'on'`: до закрытия вкладки страница работает с живой моделью.

## 3. Уровни кода (что можно писать в JavaScript)

| Уровень | Файлы | Минимум | Нельзя без перевода |
|---|---|---|---|
| Страница | `journal.js`, `story-frames.js`, `<статья>.js`, скрипты в `index.html` | Safari 14 (старые iPhone) | приватные поля `#x`, `await` вне функций, статические блоки `static {}`, ретроспективные проверки в регулярках `(?<=`, `(?<!`, флаги `d`/`v`; вызовы `.at()`, `structuredClone`, `findLast`, `Object.hasOwn`, `toSorted` |
| 3D | `js/viewer/**`, просмотрщики статей, three.js | Safari 16.0 | статические блоки `static {}`, ретроспективные проверки в регулярках, флаг `v`, `Promise.withResolvers`, `Object.groupBy`, `Array.fromAsync`, `isWellFormed` |

- **Чужие сборки** (three.js r180+, бандлы просмотрщиков) переводятся через esbuild с целью `safari15`, как в `dolina_assets.py → lower_for_safari`. Именно из-за `static {}` в three.js r187 «Долина» не запускалась на iOS 16.2.
- **Проверку делает `tools/compat_check.mjs`.** Она встроена в `make_public.py`: при ошибке выпуск останавливается.

## 4. CSS

- `svh` и `dvh` пишем как обычно. Запасной `vh` перед каждым таким правилом добавляет при сборке `compat_css.py`: без него на iOS до 15.4 закреплённые сцены схлопываются.
- `inset` при сборке тоже раскладывается на `top/right/bottom/left`.
- `aspect-ratio` у блоков без собственных пропорций (div с картинкой внутри, окно 3D) — с запасной высотой в `@supports not (aspect-ratio: 1)`.
- Контейнерные единицы (`cqw`) — с запасным вариантом в `@supports not (width: 1cqw)`.
- `<dialog>` скрыт, пока не открыт: `.lightbox:not([open]) { display: none }`. В скрипте есть замена `showModal`.
- Стили статьи пишутся только внутри `.view-<статья>`; общий файл `journal.css` не трогается.

## 5. Живая 3D-сцена: обязательные правила

1. **Рисовать только по изменению:** прокрутка, размер окна, догрузка модели. Постоянный цикл `requestAnimationFrame` запрещён: он грел телефоны и тормозил REC.
2. **Статичные тени:** `renderer.shadowMap.autoUpdate = false`. Пересчёт — только когда меняется сцена (слои, разрезы, до/после), а не при движении камеры. Не больше одной отрисовки за кадр.
3. **Пиксели:** на телефонах (`pointer: coarse`) не больше 1,5 на CSS-пиксель.
4. **Бюджет кадра на телефоне** (проверка `tools/gl_cost.py`):
   - не больше 1 500 команд рисования, цель — 1 000;
   - не больше 1,5 млн треугольников;
   - первая порция модели не больше 15 МБ, остальное догружается.

   Сейчас: REC около 740 команд и 0,27 млн треугольников. «Долина» после правок — 1,5–3,3 тыс. команд и 1,5–3,4 млн треугольников. Это выше бюджета, следующий шаг — объединить мелкие объекты модели одного материала.
5. **Загрузчик GLTF:** с исправлением определения Safari (пометка `DGC: in-app`). Без него встроенные браузеры на iPhone не грузят текстуры.
6. **Запуск при приближении:** `IntersectionObserver` и, обязательно, проверка расстояния при прокрутке и смене страницы. Наблюдатель, созданный пока статья скрыта, может пропустить первое срабатывание.
7. **Сбой:** ошибка скрипта (просмотрщик сам сообщает странице), нет ответа 25 секунд или браузер выгрузил 3D из-за памяти (`webglcontextlost`). В любом из этих случаев:
   - сцена тихо переходит на кадры;
   - кнопки 3D выключаются с подписью «3D недоступно»;
   - в строке над сценой появляется короткая пометка.

## 6. Кадры для облегчённого режима

- **Сцена с прокруткой** (глава 05 REC):
  - кадры снимаются из живой модели скриптом `tools/capture_rec_story.sh`;
  - 6 кадров на шаг для широких экранов, 3 — для телефонов;
  - соседние кадры перетекают друг в друга только в середине перехода;
  - проигрыватель — `js/story-frames.js`, без three.js.
- **Пошаговая сцена** («Долина»):
  - кадр на каждый шаг, наборы для широкого и узкого экрана (`tools/capture_dolina_keys.sh`);
  - геометрия кадра совпадает с окном модели, поэтому переход к живой модели незаметен.
- **Видео-анимация** (Blender):
  - атрибуты `muted playsinline webkit-playsinline`;
  - если видео не пошло (отказ `play()` или время не движется 2,5 секунды), анимация идёт кадрами — 10 в секунду из `assets/frames/<имя>`.
- **После любого изменения модели кадры пересняты.** Это пункт чек-листа.

## 7. Плавность прокрутки

- Не вешать неблокируемые обработчики `touchmove` и `wheel`: они заставляют прокрутку ждать скрипт.
- Обработчики прокрутки — через `requestAnimationFrame`: сначала все чтения размеров, потом все записи.
- Бегущие слова — ровно столько текста, сколько нужно на высоту окна. Постоянное «дыхание» в облегчённом режиме выключено.
- Картинки: WebP, ширина до 1650 px, атрибуты `loading="lazy"` и `decoding="async"`, ширина и высота в разметке.
- **Проверка `tools/perf_scroll.py`:** телефон, процессор замедлен в 4 раза, прокрутка пальцем по всей статье. Ни одного кадра дольше 50 мс, ни одной длинной задачи.

## 8. Выпуск и закрытые материалы

- **Предпросмотр** — закрытая копия со всеми материалами, её видит только редакция.
- **Публичный выпуск** — GitHub Pages `DoctorTima/DGC.Architects`.
- Статья с `"private": true` попадает в публичную сборку только через блок `"public"` в `journal.json`: что заменить, какие главы и источники убрать.
- Материалы, не утверждённые к публикации, в публичную сборку не попадают: сборка удаляет такие файлы и проверяет собранные страницы по списку стоп-слов. Для новой статьи с закрытыми материалами список дополняется.
- Прямая речь героев — только после записи интервью. Рабочие тексты и видео редакции в публикацию не идут.

## 9. Проверки перед выпуском

Команды из `/home/claude/build`; инструменты лежат и в репозитории, в `tools/`.

1. `python3 make_public.py` — сборка, запасные CSS, проверка синтаксиса и отсутствия закрытых данных.
2. Поднять локальный сервер на `public-out` и запустить `python3 tools/device_matrix.py http://localhost:8830` — все 7 режимов с ✓:
   - обычный компьютер;
   - компьютер без WebGL 2;
   - iPhone с iOS 15;
   - iPhone с iOS 16.2;
   - Instagram;
   - Telegram с заблокированным видео;
   - сломанная 3D.
3. `python3 tools/perf_scroll.py "<url>#<статья>" --lite` и без `--lite` — нет кадров дольше 50 мс.
4. `python3 tools/gl_cost.py <url>` — бюджет из раздела 5.
5. Проверка на настоящих устройствах: iPhone (Safari, Telegram, Instagram), iPad, Android. Chrome с подменой браузера проверяет логику, но не заменяет Safari.
6. `./sync_github.sh`, коммит, push; обновить предпросмотр.

## 10. Как добавить новую статью

1. `build/content/<slug>.html` — текст по главам: `<section class="chapter" id="…" data-chapter="NN">`.
2. Запись в `build/journal.json`: `layout`, `theme` (акцент), `edges` (три строки бегущих слов), `sections`, `sources`, при необходимости `private` и `public`.
3. Стили в `site/css/<slug>.css` внутри `.view-<slug>`, поведение в `site/js/<slug>.js`. Подключение — через `EXTRA_HEAD`/`EXTRA_BODY` в `build.py`.
4. 3D-сцена:
   - разметка со слоем кадров;
   - сцена рисует только по изменению, тени статичные;
   - снять кадры;
   - добавить статью в `tools/device_matrix.py`.
5. Пройти раздел 9.
